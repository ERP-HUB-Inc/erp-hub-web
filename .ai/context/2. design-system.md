# Design System

## Purpose and scope

Use this document when creating or changing UI in StoreVein POS. Follow [AGENTS.md](../../AGENTS.md), inspect the target screen, and reuse its established components before adding new ones.

For report-page appearance, also read [design-system-report.md](design-system-report.md), which describes the existing report layouts, visual hierarchy, cards, filters, and tables. This document remains the base design system.

This guide records verified implementation details and rules for future changes. Existing screens contain different generations of styling; a value found in one component is not automatically a global standard. Preserve the target screen's appearance unless the task requests a design change.

## UI stack and compatibility

- The current package manifest declares React 16, Ant Design 3 (`^3.26.16`), React Router 4, Bootstrap 4, and styled-components 6. Source components are primarily JavaScript/JSX.
- Use APIs supported by the installed dependencies. Existing Ant Design forms use `Form.create`, `getFieldDecorator`, and `validateFields` / `validateFieldsAndScroll`.
- Follow the target module's form and styling patterns. Do not introduce Next.js conventions, Tailwind, React Hook Form, or a TypeScript migration as part of a UI change.
- With Ant Design 3, existing patterns include `Dropdown overlay={<Menu />}`, `Modal visible={...}`, and `<Icon type="..." />`. Do not copy newer Ant Design examples without checking compatibility.

Source: [package.json](../../package.json).

## Styling sources and ownership

| Source | Responsibility |
| --- | --- |
| [global.css](../../src/themes/global.css) | Brand CSS variables and shared Ant Design overrides |
| [style.css](../../src/themes/style.css) | Legacy page layout, tables, modal content, and utility classes |
| [element.css](../../src/themes/element.css) | Legacy input and element classes |
| [responsive.css](../../src/themes/responsive.css) | Existing responsive rules, including POS and login layouts |
| [font.css](../../src/themes/font.css) | Font faces and custom icon font |
| [theme.less](../../src/themes/theme.less) | Ant Design-style Less variable definitions; verify the import/build path before relying on changes here |
| Component/module CSS and styled-components | Styles owned by a specific component or screen |

`src/index.jsx` imports Ant Design CSS followed by `global.css`. `BaseComponent` and the legacy common `Component` import `style.css`, which imports `responsive.css`, `element.css`, and `font.css`. Some modules also import Ant Design CSS directly. Check the rendered screen's cascade, specificity, and `!important` rules before deciding which declaration wins.

For a local fix, prefer the existing component stylesheet or styled-component. Scope new Ant Design overrides beneath the feature's class. Change `src/themes/` only when the requested behavior should apply across screens. Avoid adding global selectors or `!important` to solve a local layout problem.

## Colors and visual states

The following CSS variables are defined in `global.css`:

| Variable | Value | Current uses |
| --- | --- | --- |
| `--primary-color` | `#14b8a6` | Primary buttons, links, selected menu text, active tabs, input borders |
| `--secondary-cyan` | `#06b6d4` | Button/link hover and the `.text-secondary` helper |
| `--secondary-light-teal` | `#7dd3fc` | Table hover declaration in `global.css` |

Use these variables for corresponding brand treatments instead of repeating hex values. `.text-secondary` is cyan; it is not a muted gray text utility.

Other existing styles include a `#F7F7F7` body background, white table rows alternating with `#f9f9f9`, and borders such as `#ECECEC`. These are existing declarations, not a complete semantic token system. Match nearby components for headings, secondary text, disabled states, and status colors.

Important exceptions:

- `style.css` declares table hover as `#e6f7ff !important`, which can override the hover color in `global.css`.
- `theme.less` contains Ant Design defaults such as a 14px base font and a 4px base radius. Its values do not prove the rendered screen uses them.
- `global.css` does **not** impose zero radius on all controls. `.main-input input` has a zero-radius rule in `element.css`; `.ant-modal-content` has a 3px radius in `style.css`.
- Primary button hover/focus uses cyan. Input focus has a teal border and a translucent teal ring. Preserve visible focus feedback.

Use labels or icons alongside status colors. Do not invent new status-to-color or status-to-number mappings; reuse the relevant domain component and business rules.

## Typography, spacing, and layout

- `style.css` applies `'Segoe UI', sans-serif` to body text and many Ant Design components.
- `font.css` defines `enfont` using Open Sans regular, medium, and bold; `khfont` using Kantumruy; and `KhmerOS_Muol` / `KhmerOS_content`. Font availability does not mean every screen applies that font.
- Preserve English and Khmer font choices in the target screen, including print layouts. Check Khmer glyphs, line height, wrapping, and clipping when changing control dimensions.
- There is no verified universal spacing scale. Match the existing page/card/form layout. `theme.less` declares 8/12/16/24px spacing variables, but do not treat these as globally available CSS variables.
- Existing `.main-layout` uses `8px 15px` padding. The custom `PageHeader` uses `25px 40px` padding with a 28px title and 14px subtitle. These are component-specific values, not requirements for every page.
- Legacy `.main-input` and `.main-antselect` styles set some controls to 30px height. Do not force that density onto unrelated forms.
- Prefer the target screen's existing Ant Design grid, flex layout, or Bootstrap layout. Keep page titles, filters, summaries, content, and actions aligned with nearby screens.

## Shared component reference

The `@components` alias points to `src/components` in [webpack.config.js](../../webpack.config.js). Its barrel exports both wrappers and Ant Design components, with overlapping names including `Button`, `Table`, `Card`, and `PageHeader`. Inspect exports and current imports; use a direct component path when you need a specific wrapper.

| Need | Implementation | Reuse notes |
| --- | --- | --- |
| Standard controls and overlays | `antd` | Existing `Button`, `Input`, `Select`, `DatePicker`, `Table`, `Modal`, `Popconfirm`, `Dropdown`, `Menu`, and `Tag` patterns |
| Wrapped button | [Button](../../src/components/Button/index.js) | Forwards an explicit subset of props; does not forward arbitrary accessibility props or `size` |
| Decorated text field | [InputText](../../src/components/InputText/index.js) | Requires an Ant Design 3 `form`; supports label, validation, help, and input events |
| Decorated select | [Select](../../src/components/Select/index.js) | Requires `form`; uses `dataSource`, `valueKey`, and `nameKey` |
| Label with subtitle | [CustomFormItem](../../src/components/CustomFormItem/index.js) | Presentation wrapper around `Form.Item`; does not register fields itself |
| List / expanded / nested table | [CTable, TableExpand, SubTable](../../src/components/Table/index.js) | Pagination is disabled internally; `CTable.rowKey` is a field-name string, defaulting to `id`; wrappers forward only listed props |
| Heading, breadcrumbs, actions | [PageHeader](../../src/components/PageHeader/index.jsx) | Supports title, subtitle, breadcrumbs, and action elements/objects; check layout on narrow screens |
| Responsive statistic | [StatisticCard](../../src/components/stateless/statistic-card.jsx) | Includes its own `Col`; accepts a translation key through `locale`, plus value, precision, suffix, color, and column spans |
| Monetary display | [MonetaryValue](../../src/components/stateless/monetary-value.jsx) | Existing amount/sign/status styling and `Util.formatCurrency`; currency suffix is currently commented out |
| Loading indicator | [Loading](../../src/components/Loading/index.js) | Shared spinner; do not assume it accepts arbitrary `Spin` props |
| Feedback | [MessageV2](../../src/components/Message/index.js), Ant Design `message` | SweetAlert wrapper for existing blocking feedback flows; `message` for transient feedback |

Reuse is conditional on compatibility. For example, `DatePickers` in `src/components/DatePicker/index.js` renders `this.DatePicker` without defining it in that file; verify the caller before reusing it. Inspect duplicate legacy components under `src/app/modules/common/` rather than assuming they share the same props.

Do not assume a `Snackbar`, `CopyText`, or `ConfirmDialog` component exists. Locate the actual implementation before documenting or importing one.

### Example: decorated field in an existing Ant Design 3 form

```jsx
import { InputText } from "@components/InputText";

// Inside a component already supplied with `form` through Form.create(...).
<InputText
  form={form}
  name="name"
  label={nameLabel}
  required
  errorRequired={requiredMessage}
  disabled={saving}
/>
```

`nameLabel` and `requiredMessage` represent the screen's existing localized copy. Keep registration and validation in the established form flow.

### Example: existing table wrapper

```jsx
import { CTable } from "@components/Table";

<CTable
  rowKey="id"
  columns={columns}
  dataSource={rows}
  loading={loading}
/>
```

Keep pagination in the existing external control. If the screen needs features such as `scroll` that this wrapper does not forward, inspect its current direct Ant Design `Table` usage before choosing a component.

## Forms and validation

- Give controls visible labels or accessible names. Show required indicators and field-specific validation messages consistently with the surrounding form.
- For decorated Ant Design 3 forms, validate with the existing `validateFields` / `validateFieldsAndScroll` flow before submitting. Do not assume newer `Form.Item name` behavior registers fields.
- Keep invalid input visible so the user can correct it. Use field errors for input problems and the existing message/dialog pattern for operation failures.
- Disable or show loading on the submit action while saving to prevent duplicate submissions. Preserve form values on failure and existing draft/final-submit differences.
- Validate full date/time values when the business rule includes time. Preserve the screen's Moment usage, display format, timezone handling, and serialization rules.
- Reuse existing number/currency formatting and precision. Do not infer whether zero, negative, empty, or missing values are valid from styling alone.
- Preserve permission and verification rules around fields and actions, including fetching sensitive data only after required verification.

Reference existing form integration in `src/pages/Setting/Modules/Brand/form/form.create.jsx` and `src/pages/Purchasing/Orders/form/form.create.jsx`; inspect the relevant module before copying behavior.

## Tables, filters, and row actions

- Preserve column labels, order, widths, alignment, sorting, filters, totals, selection, and existing column settings unless the task changes them.
- Use stable domain IDs for row keys. Preserve existing external pagination and filter behavior; avoid applying a second client-side pagination layer to server-paged results.
- Keep loading, empty results, and failed loads distinguishable. A failed request must not silently appear as a successful empty result.
- Match surrounding numeric/currency alignment and formatters. Reuse `MonetaryValue` only when its sign/status behavior matches the domain.
- Where the screen uses a row action menu, keep it in the final action column and follow the existing `Dropdown` / `Menu` pattern. Include only applicable and permitted actions.
- Preserve confirmation dialogs for destructive actions and prevent duplicate actions while a mutation is pending.
- Keep wide tables scrollable without hiding action controls or making the whole page overflow.

Related task guides: [row action menu](../prompts/08-action-button-menu.md) and [column settings](../prompts/07-column-setting.md).

## Feedback, confirmations, and copy actions

- Reuse Ant Design `message.success`, `message.error`, or `message.warning` for transient feedback where the screen already uses it. Show success only after the operation succeeds.
- Preserve existing `MessageV2`, `Modal`, or `Popconfirm` flows for blocking feedback and confirmations. `MessageV2` exposes `swal`, `warning`, and `error`; do not assume it has a `success` method.
- Keep messages brief and actionable. Follow the module's localization pattern, including `Translate` from `@redux/index` where used.
- When an ID is displayed with an available copy action, copy only the ID. Report clipboard failure through the existing feedback pattern.
- Keep React elements out of session/local storage; persist serializable data and reconstruct the presentation when needed.
- Never display secrets or sensitive response details in feedback. Preserve existing error handling.

## Icons and accessibility

The codebase uses Ant Design 3 `Icon`, Lucide React, Font Awesome, and the custom `ca` font (`icon-*` classes in `font.css`). Match the icon family and size used in the target area. Do not introduce another icon library for a UI task.

- Use buttons for actions and links for navigation. Give icon-only actions an accessible name; a tooltip alone is insufficient.
- The wrapped `Button` forwards only selected props. Use the existing direct Ant Design button pattern when accessibility props must reach the control.
- Keep keyboard navigation, visible focus, and modal/menu focus behavior intact. Verify Escape and focus return for changed dialogs.
- Do not communicate errors, selection, or status through color alone. Check text/background contrast when adding a color combination.
- Do not replace existing navigation or permission helpers with unguarded links/actions.

## Responsive behavior

`responsive.css` includes viewport ranges at 320–480px, 481–767px, and 768px upward, plus device-specific rules. Some iPad Pro query blocks are empty; they are not evidence that a screen is fully responsive.

- Preserve the target module's breakpoints. Use scoped viewport rules for new behavior and the existing grid conventions rather than introducing a new breakpoint system.
- Allow filters and action groups to wrap without overlapping headings or inputs. Check long translated labels and Khmer text.
- Keep forms and dialogs usable within the viewport, including scrolling and reachable footer actions.
- Check affected POS layouts carefully: `responsive.css` contains rules for the retail sale left/right panels.
- Preserve print-specific dimensions and visibility when changing shared styling used by receipts or invoices.

## Verification and maintenance

For a UI change, check the affected screen in default, loading, empty, error, disabled, and success states where applicable. Check permitted/restricted actions, validation, keyboard operation, mobile/desktop layouts, and print output when affected. Run the project's relevant checks for code changes.

When extending this document:

1. Verify values, exports, and props in source before documenting them.
2. Link to the owning component or stylesheet and explain when to reuse it.
3. Distinguish a recommended rule from a legacy implementation detail.
4. Document exceptions without normalizing them through unrelated code changes.
5. Keep this file as the main design-system reference; avoid maintaining a second conflicting copy.
