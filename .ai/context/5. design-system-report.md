# Report Visual Design

## Relationship to the base design system

[2. design-system.md](2.%20design-system.md) remains the base design system for the whole application. This companion describes what the report pages look like: their composition, visual hierarchy, colors, spacing, cards, filters, charts, and tables.

Use the base guide for component compatibility, accessibility, shared behavior, and general styling rules. Use this guide for report-specific appearance. Report formulas, API contracts, and domain requirements belong in the report feature documents under `../features/reports/`.

The values below are observed source declarations, not a newly implemented token system. Existing reports have visual variants; preserve the target report's variant unless a redesign is requested. This document is based on source inspection; confirm the rendered page when matching a design.

## Visual direction

Reports have a calm dashboard appearance with a pale page canvas, rounded white panels, subtle borders and shadows, compact labels, and prominent numerical values. Purple/lavender accents distinguish report navigation; pastel icon backgrounds help separate metrics. Tables stay dense enough for comparing business data.

Keep the report's information hierarchy clear:

1. Page title and short description.
2. Report tabs and date/location/context filters.
3. Key figures or comparison summaries relevant to the selected view.
4. Section heading and explanatory text.
5. Charts, insight panels, or detailed tables.

This is a reading hierarchy, not a mandatory DOM order. Some reports place overview cards before tabs, while Purchase places filters and relevant cards inside the active tab. Do not add empty cards or charts just to fill a template.

## Page canvas and header

Sales/Financial and Purchase use a soft lavender canvas with dark purple-tinted text:

| Element | Observed treatment |
| --- | --- |
| Page background | `#f7f7fc` |
| Desktop page padding | `24px` |
| Main text/title | `#17152b` |
| Supporting text | `#8885a7` |
| Page title | `20px`, weight `700` |
| Subtitle | `13px` |
| Header bottom spacing | `20px` |

The header sits directly on the page canvas. Its Ant Design `PageHeader` has zero internal padding in these report styles; avoid adding another white header card. Product Report currently uses a more compact `20px` outer padding.

## Panels and tabs

- Main tab panels are white, with an `18px` radius, a soft lavender border (`rgba(196, 190, 220, 0.7)`), and a restrained shadow (`0 10px 24px rgba(42, 34, 85, 0.04)`).
- Existing main tab panels use `0 20px 20px` padding.
- Tabs use `13px`, weight `600`, muted purple text, and a `2px` purple (`#6c4cff`) active underline. Active/hover tab text becomes dark (`#17152b`).
- Tab spacing includes `18px` right margins and `14px 0 12px` padding in the Sales/Purchase styles.
- Use the existing report's section panels and grouping. Do not give every heading another nested card.

Purple is a report-local visual accent. It does not replace the base application's teal brand variables globally.

## Summary cards and KPI hierarchy

Summary cards combine an icon badge, a small label, and a larger value. Keep the value visually dominant and supporting notes/comparisons secondary. Use existing domain formatters for the displayed number.

| Property | Larger Sales/Purchase summary cards | Compact Product summary cards |
| --- | --- | --- |
| Minimum card height | `112px` | `88px` |
| Corner radius | `18px` | `12px` |
| Value typography | `24px`, weight `700` | `18px`, weight `700` |
| Label typography | `12px`, weight `600` | `11px`, weight `600`, uppercase |
| Icon badge | `40 × 40px`, `14px` radius | `44 × 44px`, `12px` radius |
| Card shadow | Soft purple-tinted shadow | Smaller blue-tinted shadow |

Both Product and Purchase use a `16px` grid gutter and a six-card grid that adapts through `xs={24}`, `sm={12}`, `md={8}`, `lg={4}`. Financial overview KPI cards use a four-card desktop layout (`lg={6}`); match the information density of that report rather than forcing one grid everywhere.

Existing pastel accent families include:

- Purple: `#6c4cff` on `#f1eeff`.
- Teal: `#00a890` on `#ecfffb`.
- Orange: `#f5a623` on `#fff7ed`.
- Rose: `#ff5c7a` on `#fff1f5`.

These pairs appear in the larger card variants; compact Product cards use their own related shades. Preserve semantic meaning and provide text alongside color. The `.is-blue` class can render purple in report-specific overrides, so check the owning selector rather than inferring appearance from its name.

## Filter bars and actions

Filters appear as a compact horizontal toolbar that wraps as space becomes limited. Purchase uses a `10px` gap and `16px 0` margins.

- Date/select/number controls in the Purchase toolbar are `36px` high with `10px` corners, white backgrounds, and pale lavender borders (`#ded9ee`).
- Purchase's observed desktop widths are `230px` for the date range, `190px` for store, `200px` for supplier, and `145px` for the threshold input. These widths belong to that toolbar, not every report.
- Use `13px` control/action text. Keep related controls aligned and refresh/recalculate actions close to the filters they affect.
- Standard report refresh buttons are quiet bordered actions. The Cost Changes variant uses a filled teal Recalculate action.
- Keep comparison-period copy near the related section title, smaller and muted; allow it to wrap.

Match the target report's existing date format and labels. This visual guide does not change whether filters apply immediately or require an explicit action.

## Section headings, insights, and charts

- Purchase section headings use `16px`, weight `700`, with `13px` muted description text. Its heading group has `18px 0 14px` spacing.
- Keep explanatory copy short and visually subordinate to the section title and data.
- Financial overview uses paired comparison panels and compact metric lists. Align labels and values consistently, and separate totals/comparisons from supporting notes.
- Charts should use the target report's existing container, legend, palette, grid, and tooltip treatment. Maintain stable series colors across related views and readable axis labels.
- Keep chart/panel heights consistent within the same row. Allow wide charts and legends to adapt without compressing text into illegibility.
- Insights belong near the figures they explain. Use a restrained tinted panel for supporting context and stronger alert styling only when the existing report treats the condition as a warning/error.

Do not add a graph to a table-only report or infer whether an upward change is favorable solely from its direction.

## Tables

Sales/Purchase table declarations use:

| Element | Observed treatment |
| --- | --- |
| Table text | `#0f172a` |
| Header background | `#f8fafc` |
| Header text | `#475569`, `12px`, weight `600` |
| Header bottom border | `#e2e8f0` |
| Body text | `13px` |
| Body row separators | `#eef2f7` |
| Content corner radius | `8px` |
| Pagination top margin | `14px` |

Use existing column alignment and amount/quantity formatting. Keep column titles short and long names readable through the report's established wrapping/ellipsis treatment. Preserve hierarchy between normal rows, totals, and comparison values.

Global `style.css` includes striped rows and a hover rule with `!important`; report-local hover declarations may not win. Verify computed styles and the rendered table before claiming a particular hover appearance. Check horizontal scrolling together with rounded/overflow-hidden table containers.

## Cost Changes variant

The Purchase Cost Changes tab intentionally uses a more operational slate/teal presentation:

- Light slate canvas (`#f3f6fa`).
- White filter, table, and card panels with `12px` corners and `#e1e7ef` borders.
- Subtle shadow: `0 3px 12px rgba(15, 23, 42, 0.03)`.
- A padded filter toolbar (`16px`) and filled teal actions using the base brand variables.
- A tinted red cost-hike alert with a `12px` radius, clear icon, emphasized amount/product copy, and secondary detail text.

Keep this variant scoped beneath `#purchase-report`. Do not apply its alert colors, panel background, or control rules to unrelated report tabs.

## Responsive and theme treatment

- Preserve the target report's responsive grid. In Purchase, page padding reduces to `16px` at widths up to `767px`, and date/select/number filters become full width.
- Let toolbars, section-title/comparison groups, and cards wrap naturally. Keep detailed tables scrollable within their panels.
- Check English and Khmer labels, long product/supplier names, large monetary values, and small screens before adjusting fixed heights.
- The values above describe current light styling. Dark report colors remain part of the [dark-theme plan](../features/dark-theme.md); do not document a proposed dark palette as already implemented.
- Preserve the same information hierarchy in dark mode using semantic surfaces/text/borders. Keep printable documents and report exports on their intended light document surfaces.

## Review checklist for report appearance

- Does the page match the chosen report variant's canvas, header, radius, shadow, and spacing?
- Are labels secondary and key values prominent without truncating essential numbers?
- Are filters aligned, tabs distinct, and charts/tables visually balanced?
- Are status/comparison colors meaningful and readable alongside text?
- Do responsive wrapping, empty/error/loading states, and print/export presentation remain clear?
- Are styles scoped to the report, with base component behavior and accessibility preserved?
